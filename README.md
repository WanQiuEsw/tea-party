# 随心选 · 随机选择器

零运行依赖的通用选择器。吃什么、喝什么、去哪玩，都可以创建自己的选项清单，交给随机决定。

## 使用

需要 Node.js 24+，运行 `node server.js`，打开 <http://localhost:3000>。

- 访客直接使用，无需账号。首页点击「自定义清单」，逐个输入“咖啡”“奶茶”等任意选项，保存后即可随机选择。可混合公共目录中的选项，支持多份清单、改名、移除和删除。
- 保留公共饮品目录及按品牌选择、排除、恢复功能。各选项等概率，浏览器使用 Web Crypto 生成随机数；自定义选项无需品牌和价格，也不显示虚构价格。
- 保留转盘、金光翻牌、刮刮乐、幸运号码、扭蛋、盲盒、摇一摇七种玩法，支持完整动画及快速揭晓。转盘最多显示 24 个选项，超出时其他玩法仍使用完整清单。
- 个人清单、当前选择、最近 50 次已揭晓结果、玩法和速度偏好保存在此浏览器。刷新后可回看最近结果、复制或分享；回看不再次选择。
- 不再提供普通用户、测试账号、共享抽取记录和「好运进行中」。个人选项及选择结果不会上传服务器。

## 管理员

右上角「管理员入口」登录，默认账号 `admin`、密码 `admin123`。管理员仅显示公共清单管理和选择次数统计，退出管理即可返回个人选择器。

公共清单支持搜索、分页、新增、编辑、单项／批量删除，以及 CSV 导入导出。CSV 使用表头 `奖品名称,品牌/来源,参考价值,备注`，兼容原有模板；每次导入 1—100 条，最多 5000 条。同品牌与名称的重复项跳过，格式错误整批拒绝。公共目录的参考价值仅用于展示，不影响随机概率。

统计展示今日总次数、累计次数、七种玩法各自累计完成次数，以及最近 30 个有记录日期的每日次数，按北京时间归日。只在结果揭晓时上报匿名事件 ID 和玩法，服务器记录日期；重复事件不会重复计数。预览、切换玩法、未完成刮奖和回看结果均不计数。统计上传失败时页面提示；统计反映成功上报的完成次数，不代表独立访客人数。

## 数据与升级

- 公共清单及匿名次数保存在 SQLite `tea.db`，管理员会话保存在内存中，重启后需重新登录。
- 升级启动会清除普通／测试账号、旧抽取记录、个人清单、店铺偏好及旧奖励表；保留管理员与已初始化的公共清单。旧账号数据不会迁移到访客浏览器。
- 本地数据按浏览器及站点地址隔离；清理网站数据、使用隐私窗口或更换设备后不会自动恢复。无法写入本地存储时，保存清单会提示失败，保留编辑内容供重试。
- 页面在服务启动时读入内存；更新代码后需要重启服务。更换端口可设置 `PORT` 环境变量。

## 验证

```sh
node --test tests/*.test.cjs
node tests/selector-flow.cjs
```

浏览器流程需要已安装 Playwright 和 Chrome，可使用 `NODE_PATH` 指向已有 Playwright，或设置 `TEA_BROWSER=msedge` 使用 Edge。

测试使用临时目录和独立数据库，不修改现有 `tea.db`。覆盖等概率规则、北京时间边界、CSV 校验与导入、管理员权限、旧数据清理、匿名统计及去重、七种玩法、本地清单与结果持久化、浏览器隔离、存储失败、清单改名／删除，以及 320 / 390 / 768 / 1280px 布局。手机物理传感器需要真机验收。
