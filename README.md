# 一口好运 · 奶茶随机转盘

一个零依赖的通用幸运转盘：支持奶茶、礼品等自定义奖品，管理员可维护奖品清单并查看抽奖记录。

## 功能

- **按店铺定制清单**：先选择品牌，可直接抽取，或点击「编辑我的清单」排除不想喝的饮品，确认后保存。支持恢复单款、恢复全部与取消编辑。每个账号、每家店分别保存到服务器，刷新和换设备后保留；demo 为共享测试账号，清单也共享。七种玩法与概率公示均只使用当前店铺的个人清单；抽奖中及未揭晓的刮奖／扭蛋期间不能切换清单。全部排除时停止抽取，可恢复后继续。新品默认参与，已排除饮品保持排除。
- **随机转盘**：每款奶茶对应一个扇区，抽奖结果按价格加权计算。
- **金光翻牌**：三张香槟金卡牌任选一张，AI 绘制牌背搭配旋转星轨；蓄光约 2.6 秒后翻面，再播放金光揭晓并展示奖品。所有卡牌概率相同，抽奖仍由服务器决定；动画期间防止重复开奖，支持键盘及减少动态效果。牌背 WebP 约 38 KB，无新增运行依赖。
- **刮刮乐**：独立的经典刮奖玩法，刮开 40% 自动揭晓，支持手指、鼠标和一键揭晓。
- **幸运号码**：独立的第六种玩法。含 1 个幸运号码、五排 1—5 个号码（共 15 个），每排右侧显示共用奖品；保证一个号码匹配，得到奖品或再来一次。刮开 90% 自动对奖。幸运号、票面号码与票号在生成后固定，开始刮奖仅绑定服务器奖品，不重新生成票面；已开始的票须揭晓后再切换玩法。两种刮奖玩法首次开始时向服务器开奖，预览不消耗次数。
- **幸运摇一摇**：服务器先抽取本局结果，三列依次展示相同奖品或再来一次。手机可主动开启摇一摇，也可点击摇杆或按钮。
- **统一概率**：所有玩法均为奖品 97%、再来一次 3%，没有空奖。按当前店铺个人清单的参考价从高到低排名（同价按 ID 升序）：第 1 名王者、第 2–4 名钻石、第 5–8 名黄金、第 9 名起青铜；权重分别为 `0.15 / 参考价`、`0.5 / 参考价`、`1 / 参考价`、`1.5 / 参考价`，归一化到 97%，王者为最低概率。清单不足时只显示已有档位；完整概率可在页面查看。服务器决定奖品并立即保存中奖记录，客户端不能指定奖品。
- **畅抽与每日奖励**：普通用户可以不限次数重抽，每天最多保留一份可兑换奖励；管理员不受每日兑换状态限制，可无限抽奖，保留抽奖历史，不新增或替换每日奖励。已有当天奖励时，重抽前提示确认放弃；勾选“我已了解，后续不再提示”并确认后，当前账号在此浏览器可直接重抽（仍会放弃原奖励），刷新后也生效；取消或关闭不会记住勾选。取消则保留原奖励，确认后由服务器原子替换。抽中再来一次时原奖励已放弃，可继续抽。北京时间 00:00 开启新一天，往日待兑换奖励保留。
- **我的兑换榜**：仅普通用户可见，管理员隐藏。按中奖日期展示累积的待兑换奖励；每条奖励后可单独点击兑换，成功后仅该条移入已兑换记录，其他奖励保留，不能重复兑换。兑换往日奖励不影响当天抽奖。当天奖励兑换后当天停止抽奖，第二天恢复。并发重抽、旧页面与重复兑换都由服务器校验。升级时仅将当天最新的一条历史中奖记录转为待兑换奖励，更早的旧记录保持历史记录，不批量转为兑换权益。
- **中奖自动关闭**：所有玩法中奖弹窗显示“中奖页面将在 3 秒后自动关闭”，展示 3 秒后自动关闭；仍可提前手动关闭，抽中“再来一次”继续保留操作按钮。
- **四档光效**：王者使用最强金色放射光晕、皇冠标记与粒子庆祝，钻石使用冰蓝柔光，黄金使用暖金底色，青铜保持轻量庆祝；支持减少动态效果。概率列表、转盘与结果弹窗使用同一档位。
- **登录使用**：首次打开页面默认以 `demo` 测试账号自动进入，无需密码，可无限试抽，结果不可兑换。测试账号共享抽奖记录，无管理权限；右上角「切换账号」可登录普通用户或管理员，支持返回当前账号和一键使用测试账号。有效登录在刷新后保留。
- **管理员后台**：新增、编辑和批量删除奖品，支持奖品名称、可选品牌／来源、参考价值、可选备注；查看所有用户的抽奖记录。
- **模板导入导出**：导出空白 CSV 模板或当前清单，使用 Excel / WPS 批量填写后以 CSV UTF-8 导入。导入前预览新增和重复项；同品牌／来源与名称的重复项跳过，不覆盖已有奖品。错误或超出上限时整批不写入。
- **SQLite 存储**：饮品与抽奖记录保存在 `tea.db`，使用 Node 内置 `node:sqlite`，无需安装任何依赖。
- **手机适配**：手机端单列布局，表格可横向滚动，触控按钮不小于 44px。

## 运行

需要 **Node.js 24+**（内置 `node:sqlite`）。

```bash
node server.js
```

打开 <http://localhost:3000>。

| 角色     | 账号    | 密码       |
| -------- | ------- | ---------- |
| 普通用户 | `user`  | `123456`   |
| 普通用户 | `ping`  | `123456`   |
| 管理员   | `admin` | `admin123` |

首次打开页面自动以 `demo` 进入；需要 `user`、`ping` 或管理员时，点右上角「切换账号」。切换成功前保留原会话，输错密码可重试或返回当前账号。

管理员登录后，页面下方会出现「管理奖品清单」与「用户抽奖记录」两个区域。

## 批量新增奖品

1. 管理员登录后展开「管理奖品清单」，点击「导出空白模板」。
2. 保留表头 `奖品名称,品牌/来源,参考价值,备注`，每行填写一款奖品。名称最多 40 字，品牌／来源最多 30 字，备注最多 100 字；参考价值为 ¥0.01—1,000,000，支持两位小数，用于结合档位系数按价值倒数分配概率。
3. 保存为 **CSV UTF-8**，点击「导入 CSV 模板」选文件，检查预览后确认导入。每批 1—100 条、文件最多 250 KB，清单总量最多 5000 款。

现有奶茶数据与抽奖记录保持兼容，服务启动时自动添加每日额度表。模板只支持 CSV，不支持直接上传 `.xlsx`。

## 说明

- 首次启动自动创建 `tea.db`，并导入用户最新提供的 `docs/奶茶价格表_2026-10-26.md`（`catalog.json`：14 个品牌、168 款饮品及参考价格）。已有数据库首次升级时完整替换旧奖品清单、备注、个人排除配置及店铺选择，保留抽奖历史与兑换记录。替换只执行一次，后续重启不恢复管理员删除的奖品。价格按原文保留，不代表实时门店售价。
- 会话保存在内存中，重启服务后会自动进入 `demo`；普通用户与管理员需重新登录。
- `index.html` 在启动时读入内存，修改页面后需重启服务。
- 换端口启动：`PORT=3001 node server.js`。
- 手机体感需要浏览器支持及安全上下文（HTTPS 或本机 localhost）；体感强弱不影响中奖概率。
