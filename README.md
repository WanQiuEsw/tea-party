# 一口好运 · 奶茶随机转盘

一个零依赖的通用幸运转盘：支持奶茶、礼品等自定义奖品，管理员可维护奖品清单并查看抽奖记录。

## 功能

- **揭晓速度**：七种玩法均支持「完整动画 / 快速揭晓」，默认完整动画，浏览器记住选择。快速模式跳过等待并直接显示结果，刮奖点击封面即可揭晓，扭蛋和盲盒无需二次确认；抽奖中锁定速度选择。继续使用服务器开奖结果与原有概率，完整模式仍遵循系统减少动态效果设置。

- **简洁首页**：按“选择店铺或清单 → 点一下开始 → 确认这一杯”使用，首次默认转盘。全部七种玩法可在“换个玩法”中查看与选择，也可点“随机换一个”（不重复当前玩法，并跳过超出数量限制的转盘），切换不消耗抽奖次数。浏览器记住上次主动选择的玩法，存储不可用时仍可正常使用；超限自动回退不覆盖偏好。测试账号在首页与结果中提示“体验结果不可兑换”。
- **转盘数量保护**：转盘最多展示 24 款饮品；超过时隐藏转盘入口并显示原因，当前处于转盘时自动切换至幸运摇一摇。清单中的饮品全部保留，其他玩法仍按完整清单等概率抽取，减少至 24 款以内自动恢复转盘入口。
- **命名自定义清单**：点击首页「编辑我的清单」右侧的「自定义清单」，输入 1—30 字名称，从不同品牌添加喜欢的饮品；选中具体品牌时仅显示「全选当前品牌」和「清空当前品牌已选」，清空不影响其他品牌；未选品牌或选中全部品牌时显示「全选全部奶茶」和「清空已选」，批量操作不受搜索词影响。店铺选择弹窗仅维护单店清单，自定义入口中可新建及切换已保存清单。至少选择 1 款后才能保存，名称留空时自动使用「奶茶自定义清单01」等未占用名称，保存后立即用于抽取。支持多份清单、切换、重命名、移除饮品和删除清单，按账号保存到服务器，刷新与重启后保留。每款饮品只能添加一次，品牌新品不会自动加入自定义清单。删除清单保留奶茶目录及历史抽奖记录。
- **按店铺定制清单**：点击首页「今天喝哪家？」打开弹窗，搜索店铺并查看对应饮品；在「我的清单」中移除饮品，在「快速新增」中搜索并添加已移除的饮品，也可点击「全选这家店」全部加入。确认后使用当前店铺的清单，取消则不保存。电脑端左右分栏，手机端店铺横向列表与饮品上下排列。每个账号、每家店分别保存到服务器，刷新和换设备后保留；demo 为共享测试账号，清单也共享。七种玩法均只使用当前店铺或自定义清单；抽奖中及未揭晓的刮奖／扭蛋期间不能切换清单。至少保留 1 款饮品，前后端均校验。清单为空时需添加后才可抽取。新品默认参与，已排除饮品保持排除。
- **随机转盘**：每款奶茶对应一个扇区，所有扇区等大，每款饮品等概率抽取。
- **金光翻牌**：最多展示 3 张卡牌，不足 3 款时按实际数量展示，任选一张，AI 绘制牌背搭配旋转星轨；蓄光约 2.6 秒后翻面，再播放金光揭晓并展示奖品。所有卡牌概率相同，抽奖仍由服务器决定；动画期间防止重复开奖，支持键盘及减少动态效果。牌背 WebP 约 38 KB，无新增运行依赖。
- **刮刮乐**：独立的经典刮奖玩法，刮开 40% 自动揭晓，支持手指、鼠标和一键揭晓。
- **幸运号码**：独立的第六种玩法。含 1 个幸运号码，按清单数量显示 1—5 排，每排 1—5 个号码（2 款显示 2 排共 3 个号码，3 款显示 3 排共 6 个号码，5 款起显示 5 排共 15 个号码），每排右侧显示共用奖品；保证一个号码匹配，得到清单内的奖品。刮开 90% 自动对奖。幸运号、票面号码与票号在生成后固定，开始刮奖仅绑定服务器奖品，不重新生成票面；已开始的票须揭晓后再切换玩法。两种刮奖玩法首次开始时向服务器开奖，预览不消耗次数。
- **盲盒与扭蛋**：盲盒最多展示 9 个，机内扭蛋最多展示 12 颗，不足上限时按实际数量展示，新增、移除、换店和刷新后同步调整。展示数量不限制抽奖范围，完整清单中的每款饮品均可等概率抽中；盲盒按最多三列换行。
- **幸运摇一摇**：服务器先抽取本局结果，三列依次展示相同奖品。手机可主动开启摇一摇，也可点击摇杆或按钮。
- **公平随机**：所有玩法使用同一套 `1/N` 规则，清单内有 N 款奶茶，每款概率均为 `1/N`；一款为 100%、两款各 50%、五款各 20%。价格、品牌和等级均不影响结果，不支持用户调整概率，也没有「再来一次」特殊结果。服务器决定并保存抽取结果，客户端不能指定奖品。
- **只帮你做决定**：普通用户与测试账号均可不限次数抽取；移除每日奖励、兑换榜、兑换接口和放弃奖励确认，历史抽取记录保留。旧数据库中的奖励表保留原数据，但不再读写或限制抽取。
- **结果随时可看**：弹窗显示 5 秒倒计时后自动关闭，复制或分享时暂停并改为手动关闭。右下角持续保留“本次结果”按钮，不挤占玩法区域，点击后复用结果弹窗查看、复制或分享；回看不再次抽取且不自动关闭，刷新后可查看当前账号最近一次抽取。不支持系统分享时复制文字供粘贴分享，失败或取消不会清空结果。
- **统一庆祝与好运动态**：保留抽奖动画与统一的彩纸庆祝，移除王者、钻石、黄金、青铜等级及概率展示。「好运进行时」继续展示其他用户抽中的奶茶，保留昵称脱敏与滚动效果；历史记录不删除。
- **登录使用**：首次打开页面默认以 `demo` 测试账号自动进入，无需密码，可无限试抽，结果不可兑换。测试账号共享抽奖记录，无管理权限；右上角「切换账号」可登录普通用户或管理员，支持返回当前账号和一键使用测试账号。有效登录在刷新后保留。
- **管理员后台**：新增、编辑和批量删除奖品，支持奖品名称、可选品牌／来源、参考价值、可选备注；奖品清单和抽奖记录均支持搜索，以及每页 5 / 10 / 20 / 50 条分页；管理员登录后仅展示“管理奖品清单”和“用户抽奖记录”两个板块，隐藏全部抽奖玩法、店铺选择与中奖动态；新增和编辑共用弹窗修改品牌、名称、金额和备注，搜索与导入／导出也通过按钮打开弹窗。抽奖记录分页查询全部历史，支持按用户、品牌、奖品、金额或北京时间日期搜索；批量全选仅作用于当前页。
- **模板导入导出**：导出空白 CSV 模板或当前清单，使用 Excel / WPS 批量填写后以 CSV UTF-8 导入。导入前预览新增和重复项；同品牌／来源与名称的重复项跳过，不覆盖已有奖品。错误或超出上限时整批不写入。
- **SQLite 存储**：饮品与抽奖记录保存在 `tea.db`，使用 Node 内置 `node:sqlite`，无需安装任何依赖。
- **手机适配**：手机端单列布局，表格可横向滚动，触控按钮不小于 44px。

## 运行

需要 **Node.js 24+**（内置 `node:sqlite`）。

```bash
node server.js
```

打开 <http://localhost:3000>。

| 角色     | 账号    | 密码       |
| -------- | ------- | ---------- |
| 普通用户 | `user`  | `123456`   |
| 普通用户 | `ping`  | `123456`   |
| 管理员   | `admin` | `admin123` |

首次打开页面自动以 `demo` 进入；需要 `user`、`ping` 或管理员时，点右上角「切换账号」。切换成功前保留原会话，输错密码可重试或返回当前账号。

管理员登录后，页面下方会出现「管理奖品清单」与「用户抽奖记录」两个区域。

## 批量新增奖品

1. 管理员登录后展开「管理奖品清单」，点击「导出空白模板」。
2. 保留表头 `奖品名称,品牌/来源,参考价值,备注`，每行填写一款奖品。名称最多 40 字，品牌／来源最多 30 字，备注最多 100 字；参考价值为 ¥0.01—1,000,000，支持两位小数，仅用于展示参考价值，不影响抽取概率。
3. 保存为 **CSV UTF-8**，点击「导入 CSV 模板」选文件，检查预览后确认导入。每批 1—100 条、文件最多 250 KB，清单总量最多 5000 款。

现有奶茶数据与抽奖记录保持兼容，升级不会清理旧奖励表。模板只支持 CSV，不支持直接上传 `.xlsx`。

## 说明

- 首次启动自动创建 `tea.db`，并导入用户最新提供的 `docs/奶茶价格表_2026-10-26.md`（`catalog.json`：14 个品牌、168 款饮品及参考价格）。已有数据库首次升级时完整替换旧奖品清单、备注、个人排除配置及店铺选择，保留抽奖历史与兑换记录。替换只执行一次，后续重启不恢复管理员删除的奖品。价格按原文保留，不代表实时门店售价。
- 会话保存在内存中，重启服务后会自动进入 `demo`；普通用户与管理员需重新登录。
- `index.html` 在启动时读入内存，修改页面后需重启服务。
- 换端口启动：`PORT=3001 node server.js`。
- 手机体感需要浏览器支持及安全上下文（HTTPS 或本机 localhost）；体感强弱不影响中奖概率。

`node --test tests/admin.test.cjs` 验证管理员分页、全历史搜索、参数校验与权限；设置 `TEA_ADMIN_BROWSER=1` 并配置 Playwright 后，额外验证两张表分页搜索、列表优先展示、新增／编辑弹窗保存／取消／重复校验、导入预览与去重、模板和清单导出、刷新持久化与手机布局。

`node tests/reveal-speed-flow.cjs`：使用 Playwright 与独立数据库验证七种玩法快速揭晓、防重复请求、连续刮奖、完整动画、速度偏好记忆、失败重试、存储不可用及多尺寸触控布局。
