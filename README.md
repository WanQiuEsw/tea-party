# 一口好运 · 奶茶随机转盘

一个零依赖的通用幸运转盘：支持奶茶、礼品等自定义奖品，管理员可维护奖品清单并查看抽奖记录。

## 功能

- **随机转盘**：每款奶茶对应一个扇区，抽奖结果按价格加权计算。
- **刮刮乐**：经典款与幸运号码票。号码票只有 1 个幸运号码，五排分别排列 1、2、3、4、5 个号码，共 15 个号码，每排右侧展示一个共用奖品与参考价值（含再来一次），该排任意号码匹配即获得右侧奖品。中奖号码随机出现在任意位置，全部未匹配即为空奖；保留空奖 20%、再来一次 3% 及原奖品权重，每张最多命中一份奖品。号码款刮开 90% 自动对奖，经典款 40% 揭晓；支持手指、鼠标和一键揭晓。
- **幸运摇一摇**：一次触发，三个转轮依次独立抽取，第三列停下后判奖。仅三个相同奖品 ID 中奖；任何不一致或含空奖的组合均未中奖，三个「再来一次」加送一局。手机可主动开启摇一摇，也可点击摇杆。
- **基础概率**：除幸运摇一摇外，其他玩法空奖 20%、再来一次 3%、饮品 77%。饮品权重 = `1 / 参考价`，越贵越稀有；调整价格后概率自动刷新，完整概率可在页面查看。再来一次不写入饮品记录。幸运摇一摇每列复用基础概率，某奖品整局中奖概率为单列概率的三次方，未中奖概率为剩余组合之和；页面按当前玩法公示最终概率。
- **登录使用**：打开页面默认以 `user` 自动进入，无需输入账号密码；右上角「切换账号」可登录 `ping` 或管理员账号。
- **管理员后台**：新增、编辑和批量删除奖品，支持奖品名称、可选品牌／来源、参考价值、可选备注；查看所有用户的抽奖记录。
- **模板导入导出**：导出空白 CSV 模板或当前清单，使用 Excel / WPS 批量填写后以 CSV UTF-8 导入。导入前预览新增和重复项；同品牌／来源与名称的重复项跳过，不覆盖已有奖品。错误或超出上限时整批不写入。
- **SQLite 存储**：饮品与抽奖记录保存在 `tea.db`，使用 Node 内置 `node:sqlite`，无需安装任何依赖。
- **手机适配**：手机端单列布局，表格可横向滚动，触控按钮不小于 44px。

## 运行

需要 **Node.js 24+**（内置 `node:sqlite`）。

```bash
node server.js
```

打开 <http://localhost:3000>。

| 角色     | 账号    | 密码       |
| -------- | ------- | ---------- |
| 普通用户 | `user`  | `123456`   |
| 普通用户 | `ping`  | `123456`   |
| 管理员   | `admin` | `admin123` |

打开页面会自动以 `user` 进入；需要 `ping` 或管理员时，点右上角「切换账号」。

管理员登录后，页面下方会出现「管理奖品清单」与「用户抽奖记录」两个区域。

## 批量新增奖品

1. 管理员登录后展开「管理奖品清单」，点击「导出空白模板」。
2. 保留表头 `奖品名称,品牌/来源,参考价值,备注`，每行填写一款奖品。名称最多 40 字，品牌／来源最多 30 字，备注最多 100 字；参考价值为 ¥0.01—1,000,000，支持两位小数，用于按价值倒数分配概率。
3. 保存为 **CSV UTF-8**，点击「导入 CSV 模板」选文件，检查预览后确认导入。每批 1—100 条、文件最多 250 KB，清单总量最多 100 款。

现有奶茶数据与抽奖记录保持兼容，无需迁移数据库。模板只支持 CSV，不支持直接上传 `.xlsx`。

## 说明

- 首次启动自动创建 `tea.db` 并写入 23 款奶茶；清空清单后重启不会自动恢复。
- 会话保存在内存中，重启服务后默认 `user` 会自动重新进入；`ping` 与管理员需重新登录。
- `index.html` 在启动时读入内存，修改页面后需重启服务。
- 换端口启动：`PORT=3001 node server.js`。
- 手机体感需要浏览器支持及安全上下文（HTTPS 或本机 localhost）；体感强弱不影响中奖概率。

## 验证

`node --test tests/game-rules.test.cjs tests/inventory.test.cjs`：验证概率、10 万次抽样、卡面与结果一致、单饮品及空清单，以及 CSV 解析、导出回导、导入权限、整批校验、去重与数量上限。

已安装 Playwright 与 Chrome 的环境可运行 `node tests/game-flow.cjs`（可用 `NODE_PATH` 指向现有 Playwright 包，`TEA_BROWSER=msedge` 切换 Edge）。流程测试使用临时目录与独立数据库，不改动现有 `tea.db`；覆盖中奖、空奖、再来一次、实际刮开、摇杆/键盘/模拟体感、重复点击、记录和手机布局。手机物理传感器需真机验收。
