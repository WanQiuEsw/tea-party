# 奶茶抽奖玩法扩展方案

> 现有模式：转盘、刮刮乐。本方案规划后续可加入的玩法，所有玩法共用同一套概率。
> 原则：结果先行、动画后演；概率不变；手机端优先；不破坏现有功能。

## 1. 结论与优先级

| 优先级 | 玩法 | 定位 | 实现成本 |
|---|---|---|---|
| P0 | 扭蛋机 Lucky Capsule | 最贴年轻人盲盒文化，体感摇一摇 | 中 |
| P1 | 稀有度光效（跨模式） | 把"贵=难抽"翻译成 SSR 叙事 | 低 |
| P1 | 盲盒九宫格 | 最低成本的第三模式，5 秒一抽 | 低 |
| P2 | Plinko 弹珠 | 视觉王牌，悬念最强 | 中高 |
| P3 | 奶茶签筒 / 拉霸机 | 玄学分享 / Y2K 怀旧 | 低 |

暂不做：抓娃娃机（抓不中破坏体验）、盲勺（适合多杯场景）、十连抽（与"选一杯"冲突）、物理引擎与动画库。

## 2. 通用架构：结果先行，动画后演

```
randomIndex() → drink（结果先定死）
      ↓
prepare() 重置舞台，预生成视觉诱饵
      ↓
play() 播放演出动画（纯表演，不参与概率）
      ↓
reveal() → showResult(drink) → recordDraw(drink)
```

接入点：

- 模式注册：在 `setMode()` 中增加一个分支，`#wheel-stage` / `#scratch-stage` / 新舞台通过 `hidden` 切换。
- 模式数组建议：`MODES = ['wheel', 'scratch', 'capsule', 'box', 'plinko']`，按钮由数组渲染，但**不要为 5 个模式重写现有切换逻辑**，先按现有两个按钮的写法逐个加。
- 结果复用：新玩法只调用 `randomIndex()`、`showResult(drink)`、`recordDraw(drink)`，不新增概率代码。
- 按钮文案复用 `updateSpinButton()`，按模式返回"帮我选一杯 / 直接揭晓 / 再扭一颗"等。
- 概率公示区不动：所有模式共用同一份权重与公示列表，文案写"所有玩法共用同一概率"。

验收方式：新增模式后不改 `randomIndex()` 与 `weights`，概率即与转盘严格一致；另可用 1 万次抽样脚本对比分布。

## 3. P0 扭蛋机 Lucky Capsule

### 体验脚本

1. 进入模式：粉白胶囊机身，透明球仓里 9 颗彩色胶囊（DOM 元素，非 canvas）。
2. 交互二选一：
   - 长按摇杆 0.6 秒蓄力（进度环），松手触发；
   - 手机摇一摇（`DeviceMotionEvent`），需在点击手势中申请权限（iOS 13+），拒绝或不支持则自动只用长按。
3. 演出：球仓胶囊翻滚 0.8 秒 → 一颗胶囊从出货口滚出 → 落地弹跳 2 次（0.6 秒）→ 自动开壳（左右两半旋转分开）→ 光柱按稀有度分级 → 奶茶卡从壳中升起。
4. 揭晓：`showResult(drink)`，按钮变「再扭一颗」，底部文案"再扭一颗"与刮刮乐风格一致。

### 技术拆解

- 结构：`.capsule-machine > .capsule-globe > .capsule×9`、`.capsule-body`（投币口/摇杆）、`.capsule-out`（出货口）。
- 动画：只用 `transform` + `opacity`，胶囊用 `--i` 变量错开延迟；翻滚 `@keyframes tumble`；开壳两半用 `rotateY` / `translateX`。
- 结果：蓄力结束时生成 `capsuleDrink = drinks[randomIndex()]`（与刮刮乐 `prepareTicket()` 时机一致）。
- 降级：`prefers-reduced-motion` 下跳过翻滚，直接显示开壳与卡片；无 JS 动画库依赖。
- 尺寸：机身 `width:min(100%,430px)`；移动端总高控制在 560px 内；球仓 300×260 左右。

### 风险

- iOS 体感权限可能被拒：已设计长按降级，不影响使用。
- 胶囊数量 ≤ 12，避免低端机掉帧。

## 4. P1 稀有度体系（跨模式）

- 按价格排序分位：最便宜 40% = R，中间 45% = SR，最贵 15% = SSR。
- 光效：R 无/白光；SR 金光；SSR 彩光 + 粒子。
- 文案：抽到便宜款说"日常款"，抽到贵款说"欧皇时刻"，避免"抽到便宜=亏"的失落。
- SSR 可生成一张结果卡（canvas 手绘文字，不引 html2canvas），保存分享。
- **只改叙事与视觉，`weights` 与 `randomIndex()` 一行不动。**

## 5. P1 盲盒九宫格

- 9 个礼盒，选中一个后其余变暗，盒盖 `rotateX` 翻开 + 光柱 + 卡片升起。
- 关键文案："选哪个都一样，好运已经注定"——避免用户误以为选盒子影响概率。
- 随机：点击后调用 `randomIndex()` 生成结果；9 个盒子不预置不同奖励。
- 成本最低，可作为第三模式先上线。

## 6. P2 Plinko 弹珠

- 竖屏钉板，底部 7 个槽位，槽位标签为饮品短名/品牌色。
- 点「投球」→ 球下落 1.8–2.5 秒 → 落槽高亮 → 揭晓。
- 核心算法：先由 `randomIndex()` 定结果并映射到目标槽，再让球逐帧向目标 x 插值 + 正弦抖动 + 钉子处小幅随机反弹，保证**视觉像随机、落点与结果一致**。
- 球用 DOM + transform，钉板用 CSS 伪元素/渐变绘制，不引入物理引擎。
- 支持点击跳过演出，直接落槽。
- 风险：槽位多时手机字号偏小；落点与结果不一致会"露馅"，需精确对齐。

## 7. P3 轻量备选

- 奶茶签筒：摇动签筒 → 一支签弹出 → 签文为"品牌 + 奶茶 + 今日运势"，可截图分享。低成本、玄学、贴合手账风。
- 拉霸机：三列滚动 1.2 秒后对齐品牌/名称，Y2K 霓虹风。低成本。

## 8. 验收清单（每个新模式都要过）

- 390×844 实测无横向溢出，主舞台宽度 ≤ 358。
- 转盘、刮刮乐原有功能回归通过：抽奖、结果弹窗、复制点单、历史记录。
- 概率：复用 `randomIndex()`，不改 `weights`；新增模式抽样分布与公示一致。
- 无障碍：模式按钮 `aria-pressed`；新舞台有 `aria-label`；键盘可完成抽奖；`prefers-reduced-motion` 有降级。
- 性能：动画只动 `transform/opacity`，元素数量 ≤ 15，iPhone SE 级别不卡。
- 修改 HTML 后必须重启 `node server.js`（页面在启动时读入内存）。

## 9. 明确不做

- 不引入动画库、物理引擎、构建工具。
- 不做多人/多杯/十连抽。
- 不改动概率、权重、公示列表。
- 不加抓娃娃机（必中演出也难做好手感）。
